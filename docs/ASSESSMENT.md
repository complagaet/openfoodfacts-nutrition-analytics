# Критерии оценки проекта №43

Основание: предоставленный пользователем файл `Темы_финальных_проектов_AI.docx`,
разделы I–II, обязательные задачи Cluster 8, строка темы №43 и английский раздел
III «Assessment Criteria for the Final Project (0–100 points)».
Дата разбора: **11 ноября 2026 года**.

Это матрица требований и будущих подтверждений, а не оценка выполненного проекта.
Реализация и эксперименты ещё не начаты, баллы за них не заявляются.

## Шкала и вес

Проект оценивается из **100 баллов** и составляет **40% оценки за курс**.
Уровни по каждому критерию: Excellent — 90–100% его максимума,
Good — 70–89%, Satisfactory — 50–69%, Fail — 0–49%.

| Критерий | Максимум | Что требуется для Excellent | Чем подтвердить на защите |

Первые шесть критериев дают **85 баллов**: основная работа должна обеспечивать

## Обязательные общие требования

| № в документе | Требование | Применение к теме №43 |
| --- | --- | --- |
| 1 | Не менее 5 разных функций, кроме `main` | Логически выделить загрузку, проверку, очистку, агрегацию, сравнение и сохранение результатов |
| 2 | Использовать `list` и/или `dict` | Конфигурация полей, проверки качества, результаты экспериментов |
| 3 | `if`, `elif`, `else` | Выбор операций и проверка условий |
| 4 | `for` и/или `while` | Чанки, проверки, повторяемые операции |
| 5 | Читать и записывать постоянные файлы | Исходная выгрузка, очищенный Parquet, сохранённые агрегаты |
| 6 | `try...except` минимум для одного типа ошибки | Отсутствующий файл, неподходящая схема или неверный ввод |
| 7 | Консольное меню или Streamlit/Dash с фильтрами | Предлагается Streamlit с выбором страны и категории |
| 8 | Несколько `.py`-модулей и стандартные библиотеки | Разделить ETL, аудит, SQL, эксперименты и интерфейс; использовать `pathlib`, `json`, `datetime` |
| 9 | Минимум 2 подхода и baseline | Сравнить обработку данных; отдельно выполнить прогнозную часть темы и требования Cluster 8 |
| 10 | SQLite/PostgreSQL, ER, 8+ SQL, результаты в Pandas | Обязательное дополнение к Pandas/Polars, хотя SQL не перечислен в строке темы |
| 11 | Рекомендуется минимум 500 тыс. строк **или** 200 МБ; учитывать память | Тема №43 не перечислена среди примеров исключений. Уменьшение объёма согласовать с преподавателем |

Объём 500 тыс. строк / 200 МБ в источнике назван **рекомендуемым**, а не жёстким
минимумом. При этом Cluster 8 прямо требует показать обработку данных, не
помещающихся в память. Маленькая выборка для отладки сама по себе этого не доказывает.

## Обязательные задачи Cluster 8

1. Загрузка с ограниченной памятью: чанки или построчное чтение, преобразование
   в партиционированный Parquet, `category`/downcast и измерение памяти до/после.
2. Минимум два инструмента из Pandas, Polars, Dask, PyArrow на одинаковой задаче:
   время, пиковая память, совпадение результатов.
3. Ленивые вычисления либо инкрементальные агрегаты.
4. Аудит пропусков, дубликатов, некорректных значений и дат, выбросов;
   объяснение правил очистки.
5. EDA, 4–5 визуализаций, минимум одна интерактивная Plotly;
   минимум две содержательные гипотезы с проверкой на данных.
6. Мини-дашборд с фильтрами **или** консольное меню;
   сохранение итоговых агрегатов в Parquet/SQLite.
7. Для прогнозной части — baseline и минимум две модели, метрики качества,
   разбиение без утечки данных. В теме №43 прогнозная часть прямо указана:
   **Nutri-Score prediction vs rule baseline**, поэтому этот пункт применим.

Специфика строки №43: оптимизация широкой таблицы 200+ столбцов,
аудит пропусков по странам, прогноз Nutri-Score со сравнением с правилом.
Две библиотеки обработки данных не заменяют две модели в прогнозной части.

## Сдача и дополнительные правила

- Реализация полностью на Python 3.x; запуск в стандартной консоли либо
  Colab, VS Code или PyCharm Community. В английской версии требований
  отдельно указан `requirements.txt` с версиями всех используемых библиотек.
- Сдать исходники, данные или ссылку для большого набора, README с запуском,
  письменный отчёт и презентацию `.pptx` или `.pdf`.
- Код размещается на GitHub. Для приватного репозитория к моменту проверки
  потребуется предоставить преподавателю доступ; доступ сейчас не настраивается.
- Отчёт и презентация загружаются в Moodle за 2–3 дня до итогового экзамена.
  Дата экзамена и регламент выступления в документе не указаны.
- Если программа не запускается на защите, критерии 1 и 6 получают не выше Fail.
- Пропуск обязательной задачи кластера снижает критерий 5 и связанные критерии 2–4.
- В команде критерии 1–7 оцениваются совместно, критерий 8 — индивидуально.
  Каждый участник должен понимать любую часть кода; вклад фиксируется в отчёте
  и презентации. Состав команды из трёх человек соответствует общим требованиям.
- Расширения, согласованные с преподавателем, могут дать до 5 бонусных баллов;
  итог не превышает 100. Они не заменяют обязательную часть.
- Плагиат, неуказанное заимствование кода или фальсификация результатов
  рассматриваются по политике академической честности и могут дать 0 за работу.

## Риски для оценки

| Риск | Почему он существенен | Что предусмотреть при реализации |
| --- | --- | --- |
| Ограничиться несколькими графиками | Это не закрывает Cluster 8, SQL и сравнение методов | Вести соответствие «требование → артефакт → подтверждение» |
| Показать только `DataFrame.memory_usage` | Это размер таблицы, а не пик памяти процесса | Измерять и размер данных, и peak RSS в отдельных процессах |
| Передать в модель готовый score или его производные | Ответ восстанавливается из целевой информации; результаты теряют смысл | Allowlist входных признаков и аудит утечки, разбиение до обучения преобразований |
| Смешать версии Nutri-Score | Ошибки правила могут оказаться различиями формулы или категорий | Зафиксировать версию, единицы, исключения и проверяемую когорту |
| Считать страны продаж странами производства | Сравнение получает неверный смысл | Использовать определение поля и many-to-many связь продукт–страна |
| Выдать план за результат | Нет измерений, подтверждающих выводы | Хранить фактические результаты отдельно от проектных решений |

Цель подготовки — закрыть уровень Excellent по всем критериям; гарантировать
итоговый балл до реализации, проверки результатов и защиты невозможно.
